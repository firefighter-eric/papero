# 本地验证记录

验证环境：macOS、Node.js 24.19.0、本机 LM Studio、Codex 内置浏览器。日期：2026-10-11。以下是首次 GitHub 推送前保存的本地验证快照；Production 与 PR 的交付结果另行核验。

## 阅读器实际操作

- 在 1536 × 1024 桌面视口，拖动中文滚动条，两栏停留在同一内容块；再拖动英文滚动条，两栏再次保持对应内容。中文和英文长度不同，因此两栏像素位置可以不同。
- 关闭同步后滚动英文，中文位置保持不变；开启同步后恢复对应。交换左右、单语言切换、字号调整与章节跳转保留阅读锚点。
- 滚动条支持鼠标拖动、轨道点击和 Home / End / Page Up / Page Down。macOS 自动隐藏原生滚动条时，桌面仍有可见的滚动控制。
- 在 390 × 844 手机视口，双栏上下排列；单语言模式、论文库抽屉、搜索和主题切换可用，页面没有水平溢出。64 项长署名可以展开查看，标题区域保留阅读空间。
- 主题在刷新后保留。黑色模式保留原始图像颜色，并为透明科学图提供白色底板；表格与代码单独横向滚动。
- 按用户反馈，白色和黑色主题的按钮、链接、品牌、选中状态及进度改为中性灰色；淡橙色主题保留原配色。
- FFN 公式中附带的 LaTeX 注释在前端清理时连同内容移除，避免注释标签被移除后源码作为普通文字再次显示。论文数据中的原始 MathML 与 LaTeX 注释保留；中英两栏实际显示各一个公式，均没有第二行源码。
- 参考文献链接在当前语言栏中定位；两栏的源 HTML ID 使用不同命名空间，避免跳错语言。阅读位置在刷新后恢复。
- 目录不可用、单篇文件缺失和数据身份不一致时显示明确错误；没有用虚构示例替代缺失正文。

## 数据与部署边界

原始 HTML、导入记录、模型响应和翻译检查点位于 Git 忽略的本地数据目录。发布正文使用每篇独立的 `en.html`、`zh.html`，完整保留 MathML、图像、表格、代码和引用；JSON 只保存目录与段落来源等元数据。处理后的发布目录 `paper-data/` 通过 Git LFS 管理，原始来源与调试文件不导出。默认生产构建只包含前端，`build:library` 校验并包含公开正文。独立数据地址通过 `VITE_PAPER_DATA_URL` 配置；浏览器按篇加载正文和素材。

实际以 `VITE_PAPER_DATA_URL=http://127.0.0.1:5173/paper-data` 构建，在另一端口 `4173` 运行生产预览。产物只有入口 HTML、JS 与 CSS，没有 `paper-data/`；预览正确读取七项目录，打开 Qwen3.5 的 887 个正文块和 604 个公式，首图从数据服务跨域加载成功，浏览器没有错误日志。这个检查验证分离存储路径，不代表已经上传到云端。

独立 HTML 格式另经实际生产预览验证：在 1280 × 900 视口，中英文 FFN 各显示一个公式，没有 LaTeX 注释源码；拖动中文滚动条后两栏同处 block-063，拖动英文滚动条后两栏同处 block-082。白色和黑色主题均已查看。正文从元数据中的 UTF-8 字节范围提取，再校验段落哈希；这避免浏览器把 MathML 属性中的 `<` 序列化为 `&lt;` 后改变原始内容。整文件哈希、字节范围、UTF-8 边界、段落标记和段落哈希仍分别检查。

翻译最初使用本机已有的 `qwen3.8-27b-splash`，27B、4bit、Splash 格式；用户随后允许用已有的 `qwen3.6-35b-a3b` 继续未完成部分。后者经 LM Studio 核实为 mlx-community、MLX 4bit、`qwen3_5_moe` 架构、35B。已有译文保留实际模型，后续段落记录各自的模型、参数、身份与时间，运行历史和计量按模型分别保存。公式、代码、图片与引用结构不交给模型改写。模型工作过程中的 JSON 响应不作为最终正文发布。数字与模型标识检查能发现部分错误，不能替代语义审校；译文明确标记为机器翻译，未经人工审校。

## 本地模型并发实测

使用同一个已加载的 Splash 模型、16K 上下文、`temperature: 0.1`、`reasoning_effort: "none"` 与 `/no_think`。每个配置翻译相同的四段本地编写技术文本，输出为严格 JSON；每段 ID、数字和完成状态均通过检查，12 个请求全部成功，无重试。API 对三个配置均返回 0 个思考 token。

| 总请求并发数 | 四段总耗时 | 输出 token / 秒 | 通过任务 / 秒 | 相对串行吞吐量 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 22.833 秒 | 30.307 | 0.175 | 1.000 |
| 2 | 17.466 秒 | 39.619 | 0.229 | 1.307 |
| 4 | 17.250 秒 | 40.116 | 0.232 | 1.324 |

Splash 测试后使用 2 路共享队列。4 路的总吞吐量提升很小，而单请求 P95 耗时由 8.777 秒增加到 16.589 秒。样本仅四段，按 1、2、4 的顺序运行，后续配置可能受前缀缓存预热影响；API 没有报告缓存 token，未测首 token 延迟。这些结果是本机短段落测试，不用于推算整篇论文时长。原始统计保存在 Git 忽略的 `.cache/qa/lm-studio-concurrency.jsonl`。

经用户允许临时暂停翻译脚本，等已发出请求完成后另测 `prompt-json`：移除 `response_format`，保留相同提示与模型参数。首次测试未通过 JSON 解析；兼容生产解析器允许的外层 JSON 代码围栏后，第二次测试仍未通过结构与段落 ID 校验。两次均在首次失败时停止，没有统计合格吞吐量；保留 `json_schema` 生产模式，随后恢复原翻译进程并保存已完成响应。这个有限结果只适用于当前测试提示，不能推断模型在其他提示下无法输出正确 JSON。记录位于 `.cache/qa/lm-studio-format-comparison.jsonl`。

一个脚本通过共享请求队列限制所有论文、纠错和重试的总并发；各篇论文保持单写入者，检查点顺序写入，目录更新加锁并原子替换。其他论文结束后，剩余论文可继续使用队列空出的请求槽。

首次新模型测试遇到空正文响应。实际 JSON 被 LM Studio 放到了 `reasoning_content`，与其公开问题 [#1971](https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/1971) 相同。兼容处理限定为这个确切模型、正常完成、空正文且没有工具调用；该字段必须整体是只包含全部请求 ID 的译文 JSON，然后继续执行数字、术语和结构校验，不能把一般思考文字作为译文接收。API 在三组测速中分别把 609、604、600 个 token 记为 reasoning token；这属于实际观察，不能写成零思考。`reasoning_effort:none` 和 `/no_think` 表示请求设置，当前模型没有公开的 reasoning 开关，不能据此证明推理已关闭。原始统计位于被 Git 忽略的 `.cache/qa/lm-studio-moe-concurrency-validated.jsonl`。
