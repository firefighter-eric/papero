# 首轮翻译质量比较

2026-10-11，以本库 8 组技术原文比较 **GPT-6 Luna** 与本机 **Qwen3.6 35B A3B**。本轮基本打平：Luna **137/160**，千问 **135/160**。2 分差距不足以证明整体质量有明显胜负；复杂公式跨节点的样本两者均出现实质错误。

| S02 | Qwen2：人工与自动合成标注 | 18 | 18 |
| S03 | Qwen2.5：7T 到 18T 的语料扩展 | 19 | 19 |
| S04 | Qwen2.5-VL：视频描述与时间戳 | 18 | 17 |
| S05 | Qwen3：跨公式的参数与性能比较 | 7 | 11 |

| S07 | Qwen3-VL：帧与时间编码 | 17 | 17 |
| S08 | Qwen3.5 官方文章：训练规模与精度 | 19 | 15 |

Luna 在 3 组样本得分较高，千问在 1 组较高，4 组同分。Luna 在 S08 正确保留数十万亿的量级，千问误写成数万亿。S05 中，Luna 漏掉了部分比较结论和总参数条件，千问则把原本保留的分数再次复制进翻译节点；重建后出现重复分数和语法错绑。两者在 S02 都混淆了人工与自动合成标注，在 S04/S07 都出现视觉描述被写成字幕的问题。因此首轮机械校验通过也不能替代语义复核。

这次比较使用未纠正的首次输出，测试译文与正式发布译文分别保存；没有把经过修复的发布段落作为候选答案。上述实质性问题在正式库中另行修复，库仍明确标记为未经全面人工审校的机器译文。

## 方法与边界

- 有目的选取七篇资料中的 9 个源内容块、27 个文本节点、5822 个英文字符，覆盖术语、引文、数量关系和公式接缝；不是随机全库抽样。
- 每个样本使用同一份冻结的系统提示、原文节点和完整对应上下文。提示词 SHA-256 为 `3d2d2de395d3bf090a879cb8a2c75cb37e2b1a96cf533e99d2099371677cf809`。之后生产提示增加的控制标签传输说明未加入任一候选；这组样本不含相关源码标签。
- Luna 每组由一个全新、明确指定 `gpt-6-luna` 的 Codex 子任务生成，不读取旧译文或其他候选。千问通过实际已加载的 `qwen3.6-35b-a3b` 本地 API 生成：MLX 4bit、8192 上下文、四路全局队列，`temperature=0.1`、`top_p=0.9`、`seed=42`、`max_tokens=2048`、请求 `reasoning_effort=none`。
- 双方均先保存首次响应，没有纠正或重试。格式、节点、数字与标识符机械校验通过率分别为 Luna 23/27 节点、千问 22/27 节点；完整样本分别 6/8 与 5/8。这个指标衡量协议约束，不能直接等同于翻译质量。
- 原始不可变公式与引用保持原样，按节点重建完整段落。每组随机交换 A/B，映射只由父任务保存；另一个全新 Codex 子任务只读取原文、匿名译文及评分标准。其首次评分保存后才揭示身份。
- 语义、术语、数值关系、完整性、中文流畅度分别 0–4 分，每组最多 20；扣分附最小来源与译文证据。评分是一次模型评审，有主观性，没有统计显著性检验或人工全库审校。
- 两种调用接口不同：本地 API 使用严格 JSON schema；Luna 使用 Codex 子任务，原始 API 参数与 token 用量不可得。相同的是翻译输入与提示词，不能将其称为完全受控的 API、硬件、速度或成本比较。本报告不推断实际价格优势。

原始响应、固定输入、匿名映射、机械检查和评分凭据保存在被 Git 忽略的 `.cache/qa/comparison-results/`。正文来源见 [固定论文来源](paper-sources.md)。针对这类任务，继续使用已安装的本地模型批量翻译，并对公式接缝、参数比较和标注来源进行专门检查；Luna 可作为困难片段的辅助方案，同样需要验证。
