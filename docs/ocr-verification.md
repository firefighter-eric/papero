## 五张 OCR 表格复核

使用固定官方 PDF：DQN 第 10–13 页四张补充表格和 AlphaGo 第 13 页一张补充表格。复用 LM Studio 已安装的 `mlx-community` MLX 4bit Qwen3.6 35B A3B，实际 API 模型 `qwen3.6-35b-a3b`，架构 `qwen3_5_moe`，16,384 上下文。运行时模型清单明确支持视觉，实际请求使用原图 PNG data URL，没有给模型预期答案，也没有下载新权重。

请求参数：temperature 0、top_p 1、seed 42、max_tokens 7000、reasoning_effort `none`、stream false，并行上限 2。运行时仍报告 reasoning token，因此这里记录的是请求设置，不声称推理完全关闭。DQN 大表初次整图响应达到输出上限，被排除；按原图行边界分为 1–17、18–34、35–49 三段并保留表头，三个响应均正常结束，最终覆盖全部 49 款游戏。

原始 Apple Vision（accurate、en-US、关闭语言纠错、300 dpi）的 DQN 大表输出重新运行后完全复现：294 个数值单元格中 113 个吻合、158 个漏识别、23 个识别内容错误。使用与千问相同三段图片后，239 个吻合、6 个漏识别、49 个识别内容错误。后者的 49 个错误全部是将 ± 识别成其他符号；漏识别的六格全部为数值 0。不能将 `confidence: 1` 当作已校验正确。

此次比较只支持本次这些表格的处理选择，不是通用 OCR 准确率。复杂表格优先采用千问视觉识别，按行分段并校验完整性，再独立复核；有可靠文字层的正文继续从原始文字层提取。通用导入程序本轮没有修改。
